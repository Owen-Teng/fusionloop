# FusionLoop 工作画布

[English](loop-canvas.md) · [完整示例](../examples/research-brief.zh-CN.md) · [首页](../README.zh-CN.md)

选一项边界明确的工作，先填写结果与验收，再安排动作。未知内容保留为“待确认”，不要让 Agent 代替真实负责人作出承诺。

## 基本约定

| 项目 | 填写内容 |
| --- | --- |
| 工作名称与版本 | 待填写 |
| 本次设计状态 | 草案／已确认待运行／运行中／已接受／已退回／已停止 |
| 业务发起人及授权 | 谁需要这个结果，允许投入什么资源，哪些动作已经授权？ |
| Loop Owner | 谁对本次完整交付负责，权限到哪里为止？ |
| 接收者及独立验收 | 谁能接受或退回结果？与执行者是什么关系？ |
| 参与人的容量 | 需要谁参与，工作量是否已协商？ |

## 十项运行设计

| 字段 | 要回答的问题 | 本次约定 |
| --- | --- | --- |
| 1. 触发 | 什么事件开始？输入不足时怎么办？ | 待填写 |
| 2. 可验收结果 | 交付给谁，什么状态算完成？相邻工作的边界是什么？ | 待填写 |
| 3. 唯一 Owner | 谁协调完整结果与异常？超出授权找谁？ | 待填写 |
| 4. 上下文与边界 | 可读哪些资料，适用哪个时间／对象范围，禁止使用什么？ | 待填写 |
| 5. 人的责任 | 谁决定目标、解释冲突、承担专业判断？ | 待填写 |
| 6. Agent 与系统责任 | 可以读取、分析、生成或执行哪些动作？ | 待填写 |
| 7. 人工判断点 | 发生什么情况必须停下，让谁决定？ | 待填写 |
| 8. 异常与恢复 | 缺资料、出错或超时怎样停止、升级、恢复？ | 待填写 |
| 9. 验收标准 | 接收者具体检查什么？什么情况退回？ | 待填写 |
| 10. 证据与回写 | 留下哪些记录，谁批准知识或方法变化，何时复查？ | 待填写 |

## 开始前检查

- [ ] 结果、负责人、输入与验收者已确认。
- [ ] 使用者知道 Agent 可以做什么，哪些动作必须交回人。
- [ ] 关键异常有停止与恢复路径。
- [ ] 已约定怎样记录完整周期、人工投入、返工与质量。
- [ ] 任何外部发布或真实系统变更都有对应授权。

这张画布描述工作设计。运行和验收另用[周期记录](cycle-record.zh-CN.md)，不要把勾选完成写成业务效果。
