## FridayOS 2.0 的五部分候选架构

共享团队 Agent 与工作空间维护任务和状态；组织上下文中枢治理来源、权限、版本和有效期；受控连接网络连接个人文件、云端知识、业务系统、本地节点和隔离环境；控制与审批平面管理分配、进度、异常和人的决定；知识治理与 Loop 运营管理审核发布及质量、周期、复用、冲突和风险。

成员保留各自身份，团队 Agent 在授权内读取正式团队上下文与开放的个人内容。敏感材料可留在本地或隔离环境。规则外问题应定向找到有能力且有权限的人。

## 内部 0→1 的判断标准

**第一条真实工作可由非原作者接管，得到独立验收，并把成功与失败带入下一轮持续受控改进。**

HR 同步定义跨人接管标准、人才成长路径、岗位职责变化门槛及运行记录进入绩效评价的边界。搭好架构、接通工具、完成演示，均不独立满足上述标准。

## 可选读：服务器原生团队智能工作层

![原图 13：候选团队智能工作层](../assets/paper/team-intelligence-layer.jpeg)

原稿设想在算力、模型和数据平台之上，在 ERP、CRM、EHR 等正式业务系统之间，组织五类能力：业务 Loop 与团队工作空间、组织上下文、Agent 执行引擎、治理与评测、开放连接层。既有系统继续保管交易、主数据和正式记录。

原生预集成必须在私有部署、身份权限、推理成本、安全审计、统一运维和总体拥有成本上呈现可测优势。连接器的兼容性、权限和实施成本要逐项验证。

可复制资产可能包括行业 Loop 标准包、经过真实结果检验的 Skill/Agent、连接器、上下文与审批模板、质量评测和失败样本、运行治理与复制方法。第二条 Loop、第二团队和第二客户的交付成本是否下降，是关键判断信号。

**这只是内部 0→1 成立、通过产品化门后才可能进入的 1→∞ 延展。** 它不是论文的必达成果，也不是与内部变革同时启动的第二个项目。每个客户都需重做数据、权限、流程和接口，意味着价值仍主要来自定制与顾问服务。
