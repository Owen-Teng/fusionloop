# 用 Agent 协助设计一条 FusionLoop

> 论文导读｜依据原稿第 4–7, 21–29 页整理；为便于网页阅读而重组，不是新增实证结果。


这是可复制的设计提示词，不会赋予工具、数据或对外行动权限。它依据论文第 24–29 页；输出应由有权人员审阅。

```text
请根据 FusionLoop 的组织研究协助我设计以下工作：___。
这是设计工作；不要代替我执行外部操作或作人事决定。

先区分我提供的事实、未知项和你的建议。不要补造业务数据、授权、运行结果或效果。
以“可验收的完整业务结果”为起点，填写十要素：
触发事件、业务结果、Loop Owner、输入上下文、人类责任、Agent 执行范围、
判断门、异常升级、验收标准、结果回写。

同时检查六类责任是否覆盖：Sponsor、Owner、Line Manager、Gatekeeper、
HR／人机组织设计者、技术与风险治理者。说明业务、技术和制度三类编译各缺什么。
Owner 的工作编排权只能在 Sponsor 授权和已分配容量内行使，保留专业否决与正式人事责任。

给出岗位图与工作运行图的对应关系；不根据平均提效推导编制或裁员。
设计三轨证据：业务结果、组织责任、能力执行；从 M0 基线开始判断成熟度。
M4 只能用于至少两条 M3 Loop 的受治理协同关系，不是单环自动化分数。

若涉及知识转化，按 P2C2L 五道门检查个人授权、上下文治理、工作适用、
他人独立采用、持续复用与正式化。若涉及贡献，区分直接结果、验证复用、
人才成长与继任、能力资产维护，避免重复计量，不生成统一奖金权重。

最后列明最小必要待确认项、异常接管、停止／回退条件与下一轮验证方式。
修复建议必须经过有权审核、测试和版本发布。不得把设计或演示描述为已验证。
```
