# Worked example: publishing a research method on GitHub

[简体中文](research-brief.zh-CN.md) · [Canvas](../templates/loop-canvas.md) · [Home](../README.md)

**Constructed teaching example.** Roles, rejection, acceptance, and method revision below are illustrative, not records of a team trial. Platform facts come from public sources. No method-effect measurement is made here.

## 1. Question and inputs

A researcher asks a collaborator for a brief: can GitHub serve as a first public home for a method, what should be published first, and what still needs testing?

The scope is three assigned public sources, consulted on 23 October 2026. It is not a comprehensive platform or literature review.

| ID | Source and locator | Supports | Does not establish |
| --- | --- | --- | --- |
| S1 | [GitHub profile README documentation](https://docs.github.com/en/account-and-profile/how-tos/profile-customization/managing-your-profile-readme), Prerequisites | A profile can display a nonempty root README from a public repository matching the username | Reader attention, trust, or adoption |
| S2 | [GitHub pinning documentation](https://docs.github.com/en/account-and-profile/how-tos/profile-customization/pinning-items-to-your-profile), Pinning items | Up to six repositories and gists can be pinned in total | A need to fill six slots, or an effect on growth |
| S3 | [Karpathy's LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f), opening and Architecture | An idea file describes an LLM-maintained wiki pattern for readers to develop with their agents | Universal effectiveness of this format or validation of FusionLoop |

These are brief paraphrases. Open the sources when repeating the exercise. Record inaccessible sources as missing rather than reconstructing their contents.

## 2. Completed working agreement

| Field | Agreement for this example |
| --- | --- |
| Trigger | Researcher supplies a publishing question and approves three public sources |
| Outcome | A one-page brief distinguishes platform capabilities from effects needing evaluation; the researcher accepts or returns it |
| Owner | Delegated collaborator integrates source checks, drafting, revision, and submission |
| Context | Only the specified public sources; exclude private notes, credentials, and unpublished research |
| People | Researcher sets audience and publication intent; collaborator checks facts; researcher independently reviews delivery |
| Agent | Extract source-supported facts, structure a comparison, draft, and identify gaps |
| Decision points | Conflicting or inaccessible sources, unsupported effect claims, and external publication return to people |
| Recovery | Suspend unsupported claims, keep the previous version, list gaps, and do not publish automatically |
| Acceptance | Answer the question; source material facts; separate advice from facts; avoid adoption promises |
| Learning | Retain rejection reasons and propose one research check for approval and later trial |

Authority here ends at the brief. Creating a repository or publishing is a subsequent action.

## 3. A draft that should be returned

> “GitHub is ideal for public research. Filling six pinned slots will increase reach and generate community adoption.”

Illustrative review: return. S2 establishes display capacity; none of the three sources establishes a causal link to reach or adoption. The draft also fails to specify a useful initial content package.

The owner requests removal of the unsupported effect claim and a separation of platform facts, recommendations, and open questions.

## 4. Revised brief

### Recommendation

**Use GitHub as a first public experiment for the method.** Profile and repository navigation can host an introduction and reading path, and an idea-file example exists. This supports content feasibility; reach and adoption require separate observation.

### Established capabilities

- A profile README can provide a research entry point when the documented conditions are met. [S1](https://docs.github.com/en/account-and-profile/how-tos/profile-customization/managing-your-profile-readme)
- Six is the combined pinning limit for repositories and gists. [S2](https://docs.github.com/en/account-and-profile/how-tos/profile-customization/pinning-items-to-your-profile)
- LLM Wiki illustrates an idea description that readers can develop with an agent. [S3](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)

### Initial package

Publish a clear argument, a fillable canvas, a complete teaching example, and scope limitations around one question. Link them directly from the profile so readers can understand the proposal and then try it.

### Open questions

Can readers understand the method without the author explaining it? Will they use the canvas for their own work? Which steps cause confusion or extra effort? Answer these through subsequent actual use.

### Decision boundary

This brief supports preparation for a public experiment. Publication, reuse terms, and further investment remain decisions for the researcher.

## 5. Acceptance and the next cycle

In the teaching script, the recipient checks that the question is answered, facts are traceable, recommendations are distinct, and adoption remains unproven. The revised brief is accepted within that script.

Actual use should retain sources and access dates, the first draft, rejection reasons, the revision, and the real recipient's decision. **This teaching document has no actual sign-off, human-effort measurements, or before-and-after efficiency data. Do not enter those as observed.**

Proposed method change: “In publishing or product research, check platform capability, user behavior, and adoption separately; do not infer one directly from another.”

Only an authorized approver can promote this proposal into the next method version. A different collaborator should then try it, recording whether it prevents the mistake and how much effort it adds. Omit it when the task contains no relevant inference risk.

## 6. Repeat the exercise

1. Check that all three sources still support the stated facts.
2. Give your agent the question, permitted sources, and [starter prompt](../prompts/start-a-loop.md).
3. Observe its actual reasoning errors; do not require it to reproduce the illustrative mistake.
4. Have the actual recipient review it, or explicitly label self-review.
5. Complete a [cycle record](../templates/cycle-record.md), retaining failures and unknowns.

Your outcome may differ. The difference and its explanation are useful feedback.
